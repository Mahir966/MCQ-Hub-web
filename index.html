    Technology Stack

    Six Technologies, Six Jobs

    From the Kotlin code running in your pocket to the Python scripts that keep question data clean — every technology in the project has a distinct, well-defined role.

    Kotlin

    .kt
    Runs in app

    The core of MCQ Hub — every screen, the navigation flow, and the entire examination logic are written in Kotlin.

    MainActivity.ktQuizActivity.ktQuizEngine.ktQuestion.kt

    The code is organized into packages for UI, exam logic, data, and models. Activities and fragments render the interface, while plain Kotlin classes — QuizEngine, AnswerValidator, ProgressTracker — hold the exam rules, keeping them independent of the UI and easy to test.

    Python

    .py
    Dev-time only

    Development utilities that validate the question JSON, check schema consistency, and build or merge question banks before a release.

    tools/validate_questions.pytools/build_bank.py

    Python runs on the developer's machine or in CI — it is never packaged into the Android app. The scripts catch malformed JSON, duplicate question IDs, missing explanations, and badly distributed correct answers, keeping every bundled bank trustworthy.

    XML

    .xml
    Compiled into app

    Android configuration and resources: the manifest and permissions, every screen layout, drawables, themes, and colors.

    AndroidManifest.xmlactivity_quiz.xmlthemes.xml

    Layout files define the structure of each screen; drawable XML creates rounded cards and option states; the manifest declares the app's permissions and registers its activities. All of it is compiled into the app at build time.

    JSON

    .json
    Bundled asset

    The content layer: question text, four options, the correct answer index, explanations, and subject/chapter metadata.

    assets/questions/physics.jsonassets/questions/chemistry.jsonsubjects.json

    Each question is a self-contained JSON object, so shipping a new chapter means adding one file — no code changes. The app parses these files from its bundled assets at runtime, which is what keeps the whole app fully offline.

    Gradle Kotlin DSL

    .gradle.kts
    Build-time

    The build system: dependency management, Android SDK configuration, resource processing, signing, and APK/AAB packaging.

    build.gradle.ktssettings.gradle.ktsgradle.properties

    Build scripts are written in the Kotlin DSL, making them type-safe and IDE-friendly. One Gradle task graph compiles Kotlin, processes XML resources, and produces the installable package you put on a device.

    Markdown & Properties

    .md · .properties
    Dev-time

    Project documentation and simple key-value configuration — authoring guides, README, version and flag settings.

    README.mddocs/question-format.mdgradle.properties

    Markdown guides keep contributors aligned on the question schema and app conventions; .properties files hold small configuration values consumed by the build and tooling — neither ever ships inside the app.

    Features

    Feature Mechanisms

    What MCQ Hub does for learners — and the mechanism that powers each implemented feature.

    Subject & Chapter Navigation

    A browsable library: pick a subject, drill into a chapter, and open its question set.

    Subjects and chapters come from a lightweight JSON index. Screens swap through the app's navigation component, and the back stack keeps browsing predictable.

    MCQ Practice

    One question at a time: four options, a progress header, and a clean, focused layout.

    The quiz screen renders each question from the loaded bank and moves forward question by question — no dead ends, no clutter.

    Answer Validation

    The moment an option is tapped, the app checks it against the stored answer.

    AnswerValidator compares the selected index with correctIndex from the JSON — an instant, private, on-device check with no network involved.

    Results & Progress

    Score, accuracy, and streaks after every attempt, plus progress for each chapter.

    ProgressTracker aggregates the current attempt in memory and mirrors the totals to local storage, feeding the results and statistics screens.

    Exam History

    Every attempt is saved with its date, score, and the questions you reviewed.

    HistoryStore appends each attempt as a JSON record in local storage; the history screen renders the list with dates and scores.

    Revision Notes

    Flag any question while practicing and revisit it later from a dedicated list.

    Flagged question IDs are kept in a small local set and surfaced in a revision screen, so weak spots are easy to re-practice.

    Theme Settings

    Switch between dark and light themes — the choice is remembered on every launch.

    The theme preference lives in SharedPreferences and is applied at startup, before the first frame is drawn.

    Local Data Storage

    Fully offline: questions, history, and settings all live on the device.

    Bundled assets hold the content, SharedPreferences holds settings, and a JSON file holds history. No account and no server required.
